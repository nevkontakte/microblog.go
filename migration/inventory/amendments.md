# Queued rulebook amendments

Prompt 02 queues these for the owner. The owner applies them to `migration/RULEBOOK.md`
between batches. Classifiers and reviewers don't.

1. **§4, name collisions inside one file.** `app/boxes.py` has `send_follow` and
   `_send_follow`. `tasks.py:416` calls `_send_follow` from `cmd/microblogpub`, so §4
   exports it as `SendFollow`, which collides with `send_follow`. Proposal: a private
   name that must be exported keeps a suffix that says how it differs, chosen in the
   inventory row (here `SendFollowNoNotify` or similar), and §4 lists each case.
   Source: inventory row `app/boxes.py` `_send_follow`. A second case:
   `app/indieauth.py` has `check_access_token` and `_check_access_token`, which both
   become `checkAccessToken` in `internal/web` even without an export (inventory row
   `app/indieauth.py` L429).
2. **§4, home of `AnyboxObject`.** The union of `InboxObject` and `OutboxObject` has no
   home. Proposal: an interface `AnyboxObject` in `internal/app/models.go`, next to the
   two structs. A function that returns it must return a nil interface, not a nil
   `*OutboxObject` in the interface. Source: inventory row `get_anybox_object_by_ap_id`.
3. **§2 Database, updates from SQL expressions.** At `app/boxes.py:1668-1670` and `:2121`,
   the source assigns a SQL expression to a column (`announces_count + 1`), not a value.
   The write-through rule's `session.Update` writes the Go struct's value, which can be
   stale. Proposal: add `session.Exec(ctx, sql, args...)` for these sites, with the
   expression in SQL (`UPDATE outbox SET announces_count = announces_count + 1 WHERE id
   = ?`), and leave the struct field unchanged, as SQLAlchemy does. Source: inventory
   rows `app/boxes.py` L1668 and L2121.
4. **§2 HTTP, `HTTPError` headers.** `raise HTTPException(status_code=302,
   headers={"Location": ...})` at `app/admin.py:70` sends a redirect from a dependency.
   The rulebook's `web.HTTPError` has only `Status` and `Detail`. Proposal: add a
   `Header http.Header` field that the handler wrapper copies to the response. Source:
   inventory row `app/admin.py` L70.
5. **§2 Types and values, `str.lower()`.** Python's `str.lower()` differs from Go's
   `strings.ToLower` for some characters (U+0130, the final sigma; probed). Lower-cased
   hashtags federate (`app/source.py`, `markdownify`). Proposal: a row in §2: `str.lower()`
   on text that reaches output becomes `pyLower` (home: `internal/text`), which follows
   Python's Unicode case mapping. Source: inventory rows `app/source.py` (TEXT and route
   batches).
6. **§2 Control flow and errors, httpx's error classes.** Several sites catch
   `httpx.HTTPError`, `httpx.HTTPStatusError` or `httpx.TimeoutException`. The rulebook
   maps Python exceptions to Go error types, but names no Go counterpart for httpx's.
   Proposal: in `internal/app/activitypub.go`, an `HTTPStatusError{Response}` returned
   for a non-2xx status where the source calls `raise_for_status()`, and a helper
   `isHTTPError(err)` that is true for it and for any transport error (`*url.Error`),
   as `except httpx.HTTPError` catches both. Source: inventory rows in
   `inventory.except-sonnet-4.tsv`.
7. **§2 Database, statements outside a transaction.** `app/prune.py:32` runs `VACUUM`
   after the commit. SQLite rejects `VACUUM` inside a transaction, and the rulebook's
   `Session` begins one at its first statement. Proposal: a `database.ExecNoTx(ctx,
   sql)` on the connection pool for `VACUUM` only. Source: inventory row `app/prune.py`
   in `inventory.session-sonnet-1.tsv`.
8. **§2 Database, a failed write.** With write-through, a failed INSERT or UPDATE returns
   its error at once. In the original, a failed flush puts the session into a "pending
   rollback" state: the error surfaces at the next flush or commit, and work in between
   (HTTP GETs, log lines) still runs. Proposal: the `Session` keeps the first write
   error; later statements fail with it, and `Commit` returns it, until `Rollback`. A
   call site that the original lets continue after the failure (cited in its inventory
   row) logs and continues as the source does. Source: inventory row `app/boxes.py`
   L2480 (and L1524, the `except IntegrityError: pass` that doesn't recover).

9. **§2 HTTP, Middleware: where a 500 is written** (AUDIT-EXCEPT-1, amended by the verifier). §2 HTTP, Middleware, replace the last bullet with: "From the outside, the layers are: the recover/500 layer, then ProxyHeaders, then the port of CustomMiddleware, then the mux. The handler wrapper writes only web.HTTPError responses. For any other error it calls panic with the error, without writing to the response. The CustomMiddleware port logs its line in a defer (status_code=None when nothing was written) and does not recover. The recover/500 layer recovers every panic. If the response has not started, it writes status 500, Content-Type text/plain; charset=utf-8, body Internal Server Error, with no other header. It logs the error at ERROR as uvicorn logs Exception in ASGI application." In §2, row "a bare KeyError/IndexError", replace "returns an error that becomes a 500 too" with "returns an error, which the handler wrapper passes to the recover/500 layer (§2 HTTP, Middleware)". Why: The defect is real: Starlette's ServerErrorMiddleware is outside CustomMiddleware, so the original's 500 has none of the security headers and the access log says status_code=None, and the rulebook neither fixes the layer order nor says how an error gets out of an http.Handler. The proposed text omits the charset and gives no mechanism, because a net/http handler cannot return an error outward without writing to the response.

10. **§2 Control flow and errors: a panic in a worker** (AUDIT-EXCEPT-2, confirmed by the verifier). §2 Control flow and errors, row "assert cond", replace "Each worker recovers a panic in one message, and marks that message as failed." with: "Each worker recovers a panic at the place of the source's except Exception for that message (incoming_activities.py:129 around save_to_inbox, outgoing_activities.py:258 around the send). It turns the panic into err := fmt.Errorf("panic: %v", r) and takes that handler's path exactly: the incoming worker logs, rolls back, reloads the activity, stores err.Error() in error (ADR 0023) and calls setNextTry; the outgoing worker logs, stores err.Error() in error and calls setNextTry; then the source's commit runs. A panic is not a permanent failure: only setNextTry at _MAX_RETRIES sets is_errored." Then remove "a panic would mark the message as failed at once" from rows app/boxes.py L2047 and L2175. Why: The rule's words "marks that message as failed" let one row read it as is_errored at once while another reads it as the except path; the original sends every exception in save_to_inbox or the send through except Exception, which retries with backoff, and ADR 0019 says the recovery must equal that. The amendment only makes the rule state what ADR 0019 already decides, so no ADR changes.

11. **§2 HTTP, Client: httpx timeouts are per phase** (AUDIT-EXCEPT-6, confirmed by the verifier). §2 HTTP, Client, add: "httpx's timeout is per phase, not per request. Translate httpx.Timeout(t) (the default is 5 s) as: net.Dialer{Timeout: t} for connect, Transport.TLSHandshakeTimeout and ResponseHeaderTimeout t, and a read deadline of t on each body read (a reader wrapper that resets a timer on each Read and cancels the request when it fires). Never set http.Client.Timeout. A call site with httpx.AsyncHTTPTransport(retries=n) retries a failed connect n times. The timeout error keeps Timeout() == true so that the except httpx.TimeoutException rows match it." Why: httpx applies its timeout to each connect, TLS handshake, write and socket read, not to the whole exchange, so the natural http.Client.Timeout cuts off the media proxy's streamed body after 10 s where the original keeps streaming. The amendment matches httpcore's phases, its retries=1 transport (connect retries only) and keeps the timeout test of the TimeoutException rows working.

12. **§2 Control flow and errors: except never catches a cancellation** (AUDIT-EXCEPT-8, amended by the verifier). §2 Control flow and errors, add a row after "except Exception": "Python's except clauses never catch asyncio.CancelledError (a BaseException), which wait_for and shutdown send. So no Go except translation catches a context error. In every except Exception, isHTTPError (amendment 6) and httpx.TimeoutException translation on a path that runs under a context with a deadline or a cancel, test the context first: if ctx.Err() != nil { return ctx.Err() }, and only then match, log and continue. The caller of wait_for maps that error to its except asyncio.TimeoutError branch." Then add the test to the CATCH_ALL and ERROR_MATCH rows on the incoming worker path (actor.py L55, L63, L263, source.py L154, opengraph.py L124, and the others that save_to_inbox reaches). Amendment 6 needs the same note. Why: The defect is real: Python's except Exception never sees the cancellation that wait_for sends, but in Go the expired context is an ordinary error that the catch-all logs and swallows, which adds log lines and continues work. The fix is incomplete: the same leak goes through every broad match, since amendment 6's isHTTPError and the Timeout() test of AUDIT-EXCEPT-6 are both true for a context error, while except httpx.HTTPError and except httpx.TimeoutException do not catch CancelledError.

13. **§1 Jinja2: a None that Jinja prints** (AUDIT-NONE-9, confirmed by the verifier). §1, Jinja2 row, add: "Where Jinja prints a None value ({{ x }} with x None gives the text None), the Go template prints None for nil too, with a BUG(port): marker. A template that tests the value first is unchanged." Then rows app/actor.py L120 and app/utils/indieauth.py L25 follow it, as row app/ap_object.py L255 does. Why: The rulebook does not say whether a Go template reproduces Jinja's text None, and rows L120 and L255 give opposite answers for the same behavior, which the meta-rule forbids. Printing None matches the original as §0 requires; the opposite (print nothing) is a tolerated difference that needs the owner's approval and an ADR, and the u-photo value of the h-card is read by microformats consumers.

16. **§2 Types and values: Unicode classes in regular expressions** (AUDIT-REST-1, amended by the verifier). §2 Types and values, re row, Notes, add: "Python 3 str patterns are Unicode-aware. RE2's \w, \d, \s and \b are ASCII only. Translate \w to [\p{L}\p{N}_], \d to \p{Nd}, and \s to [\t\n\v\f\r\x{1c}-\x{20}\x{85}\x{a0}\x{1680}\x{2000}-\x{200a}\x{2028}\x{2029}\x{202f}\x{205f}\x{3000}], inside and outside brackets, with the negated forms as negated classes. Never copy a \w, \d or \s from a Python pattern unchanged. RE2 can't express Python's \b: the one use (app/source.py:26, _URL_REGEX) gets an inventory row with a hand-written boundary test, using the \w class above, after each candidate match. Code points assigned after Unicode 14.0 (Python 3.11) can match in Go only: mark that BUG(port):, or ask the owner to tolerate it. The inventory lists each pattern." Why: The defect is real and the class translations are right (probed for every code point). But the amendment names \b and gives no translation, and RE2 has no Unicode \b, which _URL_REGEX uses. Go's Unicode tables are also newer than Python 3.11's, so letters assigned after Unicode 14.0 match in Go only.

17. **§1: NFKC normalization in slugify** (AUDIT-REST-2, amended by the verifier). §1, add a row: "unicodedata.normalize | golang.org/x/text/unicode/norm | NFKC in slugify (app/utils/text.py) only. Normalization stability keeps the result for every character that Unicode 14.0 (Python 3.11) assigns. Characters assigned later can differ: the owner tolerates that, or the site is marked BUG(port):." Add an inventory row for app/utils/text.py slugify (L6-8): norm.NFKC.String(text), then pyLower (amendment 5), then the Unicode-class regexes of AUDIT-REST-1, then strings.Trim(value, "-_"). The slug federates in the Article URL. Why: slugify needs NFKC, and no §1 row allows a Go module for it, so the implementer drops it or writes it by hand, and the federated Article URL changes. Normalization stability keeps the mapping of characters assigned in 14.0, so only newer characters differ, and that is a tolerated difference for the owner.

18. **§2 HTTP, Middleware: the body is parsed before the checks** (AUDIT-REST-3, amended by the verifier). §2 HTTP, Middleware, add: "On a route whose body FastAPI parses (any Form() or pydantic body parameter, in the route or in a dependency such as verify_csrf_token), FastAPI reads the body before every dependency, the app-wide 0-RTT check included. A JSON decode error gives the 422 body. Any other parse error, for example a malformed multipart body, gives web.HTTPError{Status: 400, Detail: "There was an error parsing the body"}, written by the handler wrapper as every HTTPError (so Accept: text/html gets error.html). On such a route, the body is parsed in a wrapper outside the middleware chain. The inventory names each such route." Then, in each listed row, put "(0) The form is parsed first; a parse error gives the 400 HTTPError" before the Early-Data step. Why: The order is real and the rule's middleware for the 0-RTT, session and CSRF checks runs before the body is parsed, so a malformed multipart body gives 425 or 302 where the original gives 400. The amendment writes a raw 400 JSON body, but the original raises HTTPException, so custom_http_exception_handler applies and an Accept: text/html request gets error.html with status 400. The ADR 0018 choice of middleware stays; only its order changes.

19. **§2 HTTP, Middleware: verify_csrf_token with a missing token** (AUDIT-REST-4, amended by the verifier). §2 HTTP, Middleware, add: "verify_csrf_token is not a pure middleware. When csrf_token is present and not empty, it verifies it and refuses with 403 at once, before the route's own fields are checked. When csrf_token is missing or empty, it stores a pending field required error for body.csrf_token in the request context and lets the request through. A later dependency that refuses (for example the session redirect) still wins. Then the route's own form validation writes one 422 list with the pending entry first, or the pending entry alone when there is no other error." Why: FastAPI skips a dependency whose own form field is missing and collects the error with the route's, so verify_csrf_token is not a pure lets-through-or-refuses middleware. The proposed text is right on the 403 and the two-entry body, but it calls the session check a step that validates form fields: a later refusal such as the session redirect wins over the pending error, it does not merge it. This refines the ADR 0018 statement that the CSRF check becomes middleware; the owner should note it.
